## 2026-10-21

- bin/cluster-port-forward: tunnel daemon — `daemon start|stop|restart|install|uninstall|status|logs`; one always-on supervisor owns ALL profile-tunnel children (per-key backoff 2^n cap 60s, state reloaded each tick, adopts/respawns dead rows at boot for launchd crash recovery). `daemon install` writes a launchd plist (`~/Library/LaunchAgents/com.noizu.cluster-port-forward.plist`, KeepAlive + RunAtLoad, mirroring the nx-tunnel-watchdog pattern) and loads it; manual `daemon start` fully detaches (nohup + pidfile). The daemon tears its tunnels down on stop/TERM (coherent ownership).
- share/web/: loopback-only HTTP API + web UI on `127.0.0.1:4321` (`CPF_WEB_PORT` to override) — python3 STDLIB ONLY (`http.server`, ThreadingHTTPServer, bound to 127.0.0.1). Endpoints: GET `/api/health`, GET `/api/tunnels` (rows incl. slug/ns/target/pod/dir/local/remote/state/uptime/restarts + supervisor pid + profile; 503 body still carries rows when degraded), POST `/api/up` `{profile, include[], timeout}`, `/api/down` `{slug[]|all}`, `/api/restart` `{slug}`, `/api/repoint` `{local_port, pod}` (validates the pod exists via read-only get), `/api/setport` `{slug, port}` (even ports only, persists into the profile yaml — TUI `p` semantics), `/api/reload`. Every input is regex-validated server-side AND re-validated by routing mutations through the CLI's existing profile/spec parser (hidden `__api-*` commands; server-exec'd CLIs carry `CPF_API_INTERNAL=1` so they run the local supervisor instead of re-posting — no recursion).
- share/web/index.html: vanilla-JS dashboard (no framework, no build) — same table as `status`, 2s refresh, per-row restart/stop/repoint/set-port, include+timeout bar, ns/svc drill-down filters, loud "daemon not running" hint on fetch failure.
- bin/cluster-port-forward: `up`/`stop`/`status` are now daemon clients — `up` POSTs then renders the same table/--json contract from the shared state (exit 0 iff all planned tunnels online); daemon unreachable ⇒ loud "daemon not running — cluster-port-forward daemon start (or daemon install for always-on)". `--dry-run` stays purely local; `watch`/`tui` and the legacy catalog subcommands are unchanged. `tw_state_persist` now MERGES (T_* rows win, foreign keys preserved; removal paths use `replace`) so partial `up`s don't clobber other rows.
- bin/cluster-port-forward doctor: daemon running? web API healthy? port actually bound (names the squatter — "4321 is Astro's dev-server default, that's the usual suspect")? plist present/loaded? web UI serves 200?
- Makefile: install `share/web/index.html` + `share/web/server.py` → `~/.local/share/noizu-port-forwards/web/`.
- test/: +31 assertions — daemon API on scratch ports (health, up→online lifecycle, down, repoint 400 on unknown pod + real pod, reload picks up a profile edit, setport persists + odd-port rejection), CLI-as-client, plist content assertions only (launchctl is NEVER invoked in tests), and a survivability unit (daemon + children outlive the subshell that spawned them) — suite 157/157.
